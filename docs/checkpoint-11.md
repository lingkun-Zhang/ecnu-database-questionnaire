# 第十一轮检查点 非阻断设计检查

日期：2026年10月20日。范围：完成V4的F03，在编辑和填写预览中检查不可达题、重复条件、规则遮蔽、部分重叠及不可能成立的条件。提示用于帮助核对问卷设计，不阻止合法定义发布。本轮没有开展停止流程或第一阶段最终冻结。

## 完成的行为

新增[设计分析模块](../backend/app/design_checks.py)，仅在创建者的预览接口通过原有定义校验后运行，给求值结果增加`warnings`数组。每项均含`code`、`message`、`questionId`、`ruleId`、`field`及数组形式的`relatedRuleIds`；题目级提示的`ruleId`为null，无关联规则时`relatedRuleIds`为空数组。题目和规则保留稳定ID，字段路径仍使用原始定义中的数组位置，按优先级分析不改变编辑顺序。

| 提示代码 | 判断含义 |
|---|---|
| unreachable_question | 从入口沿全部默认与条件连线仍无法到达的题目 |
| duplicate_rule_condition | 与较高优先级规则的规范化条件重复 |
| shadowed_rule | 当前条件的全部有效答案已被较高优先级规则覆盖 |
| overlapping_rules | 当前条件有部分有效答案与较高优先级规则重叠 |
| unsatisfiable_rule | 在题目允许的有效答案范围内，当前条件不可能成立 |

单选题枚举全部合法选项，以集合精确计算条件组合、交集和累计覆盖。数字题将条件树转换为有效数值区间，按allOf取交集、anyOf取并集，并结合题目上下限、integerOnly及求值器的安全数值范围。严格大小比较使用相邻可表示浮点数处理开端点，整数模式按整数边界处理，不用随机样例推断覆盖。

对后出现的每条规则，最多给出一个规则提示：有效匹配集合为空时提示不可成立，否则依次考虑重复、完全遮蔽、部分重叠。关联规则只列出确实贡献有效覆盖的先匹配规则，按优先级排列。可选题未答时仍采用原求值器的默认去向；关于规则覆盖的判断针对已回答且合法的值，不改变缺答语义。

多选题只检查可安全规范化后的重复条件，例如集合值顺序、组合子条件顺序和重复子节点；不宣称证明任意多选条件的重叠或遮蔽。不可达检查采用完整的结构图，包括可能无法命中的条件连线；它能确认没有结构路径的题目，不宣称找出所有语义不可达题。界面的“检查范围”明确说明这些边界。

非法定义仍通过原有422和fieldErrors阻断预览及发布；分析函数接到非法定义时返回空数组，不能用它替代定义校验。原有domain/evaluate、发布条件、公开填写求值、答卷提交和持久化语义不变，warnings不会写入草稿、发布快照或答卷。没有增加依赖。

## 编辑交互与过期结果保护

编辑页增加独立“检查设计”按钮，填写预览也自动带回检查结果。提示显示具体原因、可定位的题目或规则，以及关联先匹配规则的序号和优先级。点击或键盘回车可从预览返回设计页，等待编辑器与目标控件挂载，再滚动并聚焦。

提示复用上一轮的稳定ID定位和JSON兜底。提示控件使用琥珀色边框，`aria-describedby`指向实际提示文字；仅有warning时不设置`aria-invalid`，不伪装成发布错误。JSON高级编辑中已有未应用缓冲时，兜底定位沿用既有保护，不覆盖用户输入。

提示上下文受会话、问卷ID、定义快照、编辑代次及预览请求序号约束。修改已应用定义立即清空旧提示、标记和定位入口；退出或切换账号清空检查状态，离开编辑页后不接收其迟到结果，较旧请求不能覆盖较新检查。点击定位前后再次核对上下文。

界面区分“尚未检查”和“检查成功但没有提示”。仅当接口确实返回warnings数组时才建立检查结论；缺失该字段时保留未检查状态，并显示“本次没有返回设计检查结果，请确认服务已更新后重试。”，避免把服务未更新误报成零提示。零提示时使用“在已支持的检查范围内，未发现设计提示”，并保留检查范围说明。

## 真实浏览器验收

沿用AI测试账号browser_1020_01，新建独立问卷“设计检查验收 2026-10-20”，通过界面应用并保存六题定义，草稿修订1。入口数字题允许0至100的整数，设置以下规则；另有一题q_orphan没有入边：

| 规则 | 优先级及条件 | 预期设计提示 |
|---|---|---|
| r_first | 10，数字小于50 | 先匹配规则，无自身提示 |
| r_duplicate | 20，数字小于50 | 重复条件 |
| r_shadow | 30，数字小于40 | 完全遮蔽 |
