# 第十二轮检查点：安全停止与重启

2026年10月20日实现，10月21日完成实际验收。范围为F04启停流程，没有同时开展干净安装、性能实验或第一阶段最终冻结。

## 使用结果

双击`Stop.cmd`会先让本项目后端正常退出，再正常关闭本项目MongoDB；再次双击`Start.cmd`继续使用原数据。重复启动会沿用已识别的本项目实例，重复停止也能正常完成。服务最终保持运行，健康检查为ok。

实际完成两次正常停止与恢复。验收前、中间恢复和最终恢复的业务文档与配置摘要完全一致：users为2、surveys为5、survey_versions为5、responses为6；`.env`字节摘要相同。本轮没有创建账号、问卷、版本或答卷。摘要采用排序后的规范BSON JSON，对比的是完整文档内容，不只比较份数；证据不包含密钥或用户文档全文。

## 实现与身份边界

- 新增[停止入口](../Stop.cmd)、[停止脚本](../scripts/stop.ps1)和[共享身份检查](../scripts/lifecycle.ps1)，更新[启动入口](../Start.cmd)、[启动脚本](../scripts/start.ps1)与[数据库启动](../scripts/mongo.ps1)。CMD入口保存PowerShell退出码，失败时不会被pause吞掉。
- [后端运行器](../scripts/run.py)记录真实服务PID、launcher PID、随机实例标识及绝对路径。Windows虚拟环境的启动进程和实际提供8000端口的Python进程不同，不能只停止旧backend.pid指向的launcher。
- 共享检查同时核对CIM进程路径、完整命令行参数、父子关系、创建时间、实例标识、监听端口及数据库实际参数。命令行通过Windows原生分词解析，不用名字或路径前缀猜测。健康接口返回ok也不能单独证明是本项目。
- 后端停止使用项目内部的两字段JSON请求，必须匹配真实PID和当前实例标识；运行器设置Uvicorn的正常退出标志。错误、损坏、超限或旧实例请求不触发停止；正常退出只清理自身的记录。没有新增网络关闭接口，控制标识不写入日志。
- 停止脚本先核对后端和数据库双方归属，再执行任何停止动作。后端未正常退出时，不强杀进程、不继续关闭数据库。MongoDB在同一会话中复核PID、dbPath、端口、回环地址和副本集后发送正常shutdown，最终核对原身份进程退出和端口释放。关闭请求发出后的等待默认30秒，不将此数值解释为所有网络调用的总时限。
- 以规范化绝对项目路径命名的Windows互斥锁避免多个启停操作竞争。控制记录原子写入；运行目录和记录为链接时拒绝使用。业务数据目录、`.env`及历史日志不删除。

`.runtime/backend.instance.json`、`backend.process.json`、`backend.stop.json`、`mongod.process.json`是本机运行材料，随`.runtime/`被忽略，不属于公开API、MongoDB业务Schema或提交包内容。原业务API、题目求值、发布和统计逻辑没有修改，也没有新增依赖或前端构建。

## 实测发现及修正

10月20日对旧运行器完成一次经路径和父子关系确认的迁移，旧代码没有正常退出握手，不能把该次迁移写作新停止流程验收；MongoDB当时保持运行。保存的10月20日摘要也与本轮最终业务内容一致。

实测发现并修正：MongoDB进程号需要由mongosh显式转换为数字，避免Long被序列化成high/low对象；MongoDB 6.0.29的参数字段是replication.replSet，兼容replSetName；Windows PowerShell 5.1的File.Replace空字符串绑定问题改用NullString；PowerShell 7.5默认将ISO日期变成DateTime，读取身份记录时保留原日期字符串和亚秒精度。对应代码已纳入最终测试和真实启停。

10月20日一次工具审批因账户额度限制未能完成，计划的停机动作没有执行。10月21日用户继续后，按正常审批执行，没有绕过审批；本轮最终结论只来自已实际执行的记录。
