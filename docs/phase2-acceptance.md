## 八项新增要求的核对

| 明确要求 | 当前实现与验收依据 | 解释及实际边界 |
|---|---|---|
| 保存并重复使用题目 | 独立题目系列、不可变内容版本、卷内实例及显式来源；从本人或共享题目选具体版保存、发布 | 旧本地题继续使用，不按相同题干自动补造独立身份。[固定引用](phase2-question-reuse.md)、[结果](evidence/phase2-question-reuse-results-20261025.json) |
| 共享给其他用户使用 | 指定账号使用授权、撤销与重新启用；只读接收列表、选题及后端权限核对 | 使用权不包含编辑、恢复、转授权、问卷管理或答卷访问。[共享后端](phase2-question-sharing.md)、[页面结果](evidence/phase2-sharing-ui-results-20261026.json) |
| 修改不影响已发布问卷 | 内容版本只追加；问卷固定具体版，同时冻结完整发布定义和来源；旧填写凭据按原版解释 | 修改题目、恢复内容和更新题库均不自动替换旧问卷。[固定引用结果](evidence/phase2-question-reuse-results-20261025.json)、[两版演练](phase2-upgrade-rehearsal.md) |
| 记录历史并恢复 | 可查看历史、基于指定历史版派生；恢复由服务器复制旧内容并形成新版本，记录来源与恢复前当前头 | 恢复不是把当前指针直接退回旧号，也不覆盖或删除已保存历史。[恢复说明](phase2-question-restore.md)、[结果](evidence/phase2-question-restore-results-20261025.json) |
| 不同版本同时存在 | 各问卷分别选版、换版；题库成员固定某版；跨卷统计分版本展示 | 不将不同题型、量纲或选项语义自动混算。[题库页面结果](evidence/phase2-banks-ui-results-20261027.json)、[统计说明](phase2-question-statistics.md) |
| 查看被哪些问卷使用，并决定是否创建新版本 | 本人使用查询、作者本人/他人引用影响查询；保存和恢复前检查，明确确认才建版，取消保留原版 | 他人问卷显示稳定脱敏代号；不创建新版对应取消，不覆写历史。此为实现解释，见下文。[影响说明](phase2-question-impact.md)、[结果](evidence/phase2-question-impact-results-20261027.json) |
| 管理题库 | 私有题库、固定版本成员、收录、显式换版、移除、归档恢复及问卷选题 | 题库为整理关系，不扩大题目共享权；成员变化不传播到已存问卷。[题库后端](phase2-question-banks.md)、[题库界面](phase2-question-banks-ui.md) |
| 跨问卷统计同一道题 | 从真实发布来源固定问卷各自序号，按内容版本汇总四题型；本人明细/CSV；他人单独授权汇总 | 不按题干合并旧题，不提供跨卷唯一人数，不泄露他人原始答卷。[统计说明](phase2-question-statistics.md)、[结果](evidence/phase2-question-statistics-results-20261027.json) |

上述是功能、代码和证据对应关系，不能由“已有相似功能”直接推断达标。例如原单卷统计不能代替跨卷统计，原本人使用列表不能代替作者对他人引用的影响检查，发布快照也不能代替独立题目的版本历史。

## 已确认的规则与采用的解释

用户明确确认了两项权限决定：撤销题目共享后保留服务器当前草稿已保存的同一固定绑定，但禁止新增实例、新卷引用和换版；本人问卷自动纳入单题统计，他人问卷须由其所有者另行授权给题目作者且只提供汇总。已有引用解绑并保存后不再享有原保留资格。统计授权与题目使用共享分别管理。

任务书未规定以下细节，当前采用并在报告中明确说明：所有已保存内容版不可变；“是否创建新版本”通过检查后确认或取消实现；他人使用影响以稳定代号代替真实标题和身份；题库为私有整理；跨版本结果分别解释；统计范围业务有效30分钟、创建回执保留7天，CSV最多20000条且不超过8MiB。这些不是任务书原文，也不应写成教师已经逐项认可的结论。

仍可能影响课程展示口径的是“哪些问卷”是否要求跨用户真实标题，以及“不创建新版”是否另有课程指定含义。当前选择兼顾历史保护与问卷隐私，已提供真实引用条目和取消交互。若教师另给出明确解释，再按其要求调整权限和界面；不为假设中的评分方式主动开放他人标题或覆盖历史内容。

## 最终验证批次

2026年10月27日完整后端484项通过、3项既有Windows符号链接权限相关跳过、251个子测试通过，185.31秒；JUnit有487个testcase元素，不能将子测试与它们合并成独立测试数。完整前端204项通过、0失败/跳过，4596.8206毫秒，类型检查和生产构建通过。数据见[最终结果](evidence/phase2-delivery-results-20261027.json)和[构建日志](evidence/phase2-delivery-build-20261027.txt)。

新增四项共享使用授权恢复验证先定向通过（2.75秒），再包含于484项完整后端：真实提交后驱动返回异常可恢复；真实写后新增/撤销故障全部回滚；提交成功且恢复读取失败时保留结果未知，后续原请求恢复；随后撤销不能被晚到旧激活复活。它们使用真实MongoDB读写和明确的受控故障点，不是模拟成功存储或真实断网实验。见[测试源码](../tests/test_question_share_recovery.py)。

历史真实页面分别覆盖题库数字题V1/V2的0/3、共享撤销留用、影响单选题取消/派生/恢复，以及跨卷数字题独立汇总授权。受控组件测试执行真实Vue逻辑并控制HTTP，没有挂载DOM；四题型、多版本和故障矩阵由对应后端/组件测试补足。没有声称所有分支都在浏览器重演，也没有为本轮新增一次干净安装或大规模性能结论。历史批次、定向批次及浏览器检查点均不相加。

## 兼容与原数据保护

原四集合核心结构、领域引擎、发布快照、提交与单卷统计继续使用；旧格式来源字段可选，不改写旧答卷、不按题干猜来源、不批量将schemaVersion改为第二阶段。初始化增加或更新约束和索引，失败时不清库、不静默修正不合法数据。

[真实两版四副本演练](phase2-upgrade-rehearsal.md)已使用第一阶段精确基线创建旧数据，再在归属明确的合成副本完成升级、混合库旧程序行为、当前程序重启及升级前备份恢复。升级初始化前后原四集合全文不变，旧凭据仍按原版提交；直接让旧程序管理混合库时保存/发布/提交实际失败且无部分写入。恢复升级前备份可以使用旧程序，但不保留升级后的写入，因此不属于无损降级。没有在真实业务库执行迁移或回退。

最后测试随机库清理完毕，专用Mongo核对归属后正常退出、端口关闭；桌面原项目163个已比较文件哈希仍与最初基线一致，见[收尾记录](evidence/phase2-delivery-shutdown-20261027.json)。这163个指的是已有比较清单，不泛称已检查所有磁盘文件。真实配置、密钥和个人答卷没有作为本轮报告输入。
