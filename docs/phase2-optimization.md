# 第二阶段查询与页面加载优化

记录日期：2026年10月29日。基于本地提交4392fa6继续，第一阶段99b66d1保留。本轮按只读审查发现的五处问题逐项改动，没有新增题型、共享权限或另一套数据存储。

## 改动及兼容

| 原问题 | 当前处理 | 保留的行为 |
|---|---|---|
| 第11版明细在翻汇总页前显示选项ID | 本人明细附带固定版本解释的displayValue，单选为文案、多选为文案数组；界面直接显示 | 原value仍是稳定ID，CSV仍导出原值；他人来源仍无原始明细 |
| 20条题目列表产生21次HTTP读取 | 列表可选includeCurrentVersion，返回同一快照内批量取得的当前题干、题型及版号摘要 | 默认旧返回不变；打开、选用、保存仍核对完整版本及权限 |
| 统计逐来源/实例重复读元数据 | 同次快照内按ID去重批读；完整发布内容按最多32个来源的窗口加载和淘汰 | 每个新请求及事务重试重新检查授权；不跨请求缓存权限 |
| 编辑器预读所有完整发布历史 | 可选summary历史页，仅首100条；更早摘要主动翻页，比较/查看/复制/统计时按需读完整定义 | 默认完整API、历史复制来源、忙碌锁及迟到响应防护保留 |
| 影响查询从全部问卷逐卷关联 | 草稿和发布来源索引取得有序候选，同快照归并去重，每100个ID核对真实问卷并累计总数 | 孤立快照排除、当前/历史判断、他人脱敏和全局分页语义保留 |

统计明细的复合游标仍按来源、提交序号和卷内实例定位；只把可提前应用的序号下界加入展开前过滤，展开后仍做严格过滤，避免同一答卷的多个实例跨页时丢项。

完整发布缓存最多32份，题内容缓存只保留该窗口实际涉及的版本。一份发布可以包含同题不同版，因此不能把它概括为永远最多32个内容版本。新增37来源/37版夹具中，每个来源只有一个目标题版本，才观测到两类缓存均不超过32；没有声称测过RSS或所有规模的内存峰值。CSV仍受20000条、8MiB限制。

本轮不改十二集合的字段校验器，不回填或重写历史数据；只增加surveys上的两个来源索引ix_surveys_question_impact和ix_surveys_question_version_impact，原索引保留。新索引以题目标识开头，支持跨所有者的候选发现；原ownerId开头的索引仍服务本人使用查询。两个新索引额外占用磁盘空间，新增、移除或换版来源时需要维护；本轮没有测量索引大小或写入吞吐。升级幂等与十二集合全文保护另有真实数据库用例。

统计对照是在当前ASGI路由和鉴权层中分别使用4392fa6冻结统计服务类与当前类，实际数据库、范围和请求相同；不是两套全应用部署或干净安装。只统计四类元数据find，原responses聚合次数没有被声称减少。全部find来自MongoDB profiler，未模拟成功存储。

影响实验先用真实API建立模板，再明确使用通过实际BSON校验器的合成克隆扩展无关规模；不是1042次用户完整操作。七轮交错、局部暖缓存的中位数为旧457.9572毫秒、新29.9519毫秒。它说明该输入下的收益，不是大规模负载、并发吞吐或所有机器上的速度保证。

页面使用临时密钥与归属随机库，夹具通过真实API准备20题、30个内容版本、11问卷、13发布和1份匿名选择答卷。仅本人单选场景在浏览器复演；多选文案、共享撤销、201版摘要分页及故障分支由API或组件回归覆盖。整理期间范围超过30分钟后，来源子记录按TTL回收，根回执仍保留；清理核对按实际过期状态处理，没有把正常回收写成业务数据丢失。截图、账号与原始读取轨迹保持私有，服务与自建库已正常清理。

本轮未调整认证算法、MongoDB默认资源参数、部署方式或真实业务配置。进一步的负载能力和缓存预算应另做测量；当前性能结论只限上述样例。开发中的测试夹具错误、缓存边界修订和页面定位工具失败见[AI日志](ai-log.md)，没有补写个人手工贡献或第一次即通过的过程。
