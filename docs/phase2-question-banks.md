# 题库与固定版本成员的后端基础

本页保留题库后端批次的实现与验证。后续题库管理、选题及真实浏览器验收已接入，见[题库界面说明](phase2-question-banks-ui.md)；下文没有UI的表述是当时范围。

记录日期：2026年10月26日。从本地提交 `e32b076` 继续，第一阶段基线仍为 `99b66d1e637fa3b4ecb13719c0230ecb7e958701`。本步在已有独立题目、版本、共享及问卷来源机制上增加题库后端，不改写原问卷执行定义、发布快照或答案结构。

## 明确要求与本步选择

任务书第七项明确要求管理题库、加入题目、从题库选题和更新题目版本，没有指定题库的所有权、共享方式或成员模型。已有“题目管理”列表只管理独立题目，不能直接认定为题库。

本步采用以下设计选择：题库归当前账号私有；可收录自己的题目及当前有效共享的题目；一个题目系列在一个题库中最多占一个条目，条目固定具体版本。不同题库可以收录同题及不同版本。题目作者推进当前版本时，题库条目保持原版，必须明确指定版本更新；题库变更也不会替换问卷中已有的固定引用。

题库用于整理题目，不产生新的读取、编辑、转授权或答卷权限。共享被撤销后，已有条目保留为不可用记录；不能经题库读取被撤销题目的内容、更新条目或向问卷新增引用。服务器已保存问卷中原有精确绑定的留用规则，继续由原来源验证逻辑决定，题库成员不能代替这一资格。

题库可以改名、修改说明、归档和恢复。归档后本人仍可查看、修改元信息及恢复，但不能调整成员。移除成员只删除整理关系；归档题库或移除成员都不删除独立题目、题目版本、问卷来源、发布快照和旧答卷。本步不提供删除整个题库的接口。

## MongoDB结构与索引

题库及成员分为两个新集合，内容仍只存于原 `question_versions`。这样既避免复制题干和约束，也不把不断增长的成员数组塞入一个题库文档。MongoDB官方建议对可能无界增长的数组使用引用等方式控制文档增长；这里据实际访问和增长方式选择独立成员集合，不是任务书指定的集合结构。[官方建模依据](https://www.mongodb.com/docs/manual/data-modeling/design-antipatterns/unbounded-arrays/)

| 集合 | 关键字段与用途 |
|---|---|
| `question_banks` | `_id/ownerId`表达身份与归属；`name/description/archived`表达整理信息；`revision`统一控制元信息和成员决定；`creationKey/creationDigest`保存创建身份；可选`lastRequestDigest`恢复最后一次变更；另有时间和`schemaVersion` |
| `question_bank_items` | `_id/bankId/questionId/questionVersionId`固定题库成员与版本；另有创建、更新时间及`schemaVersion`，不复制内容或共享授权 |

新增四个索引：题库唯一 `(ownerId, creationKey)`；本人题库分页 `(ownerId, archived, _id)`；成员唯一 `(bankId, questionId)`；成员分页 `(bankId, _id)`。两个唯一索引分别防止创建重试产生同身份题库、同库重复收录同系列。分页索引服务实际查询，不为尚未实现的“全部归档状态”列表提前增加索引。索引会增加存储和写入维护成本，本步不据此声称已完成性能压测。

两个集合新增严格BSON校验器，限制字段、类型、长度和修订范围。跨集合的题库归属、题目授权、版本确属该题等关系由服务端检查，不能把这些关系说成校验器已经自动保证。旧七集合的文档格式不调整，初始化仍使用原有增量建集合、校验器和索引的流程，不为旧题或旧问卷补造题库关系。

## API契约

所有接口要求登录，只能管理、查看本人题库。下面的版本ID和题目ID是已有真实实体，不按标题猜测关联。所有变更成功都返回题库白名单视图 `id/name/description/archived/revision/createdAt/updatedAt`，不返回内部摘要、创建键或账号ID。

| 方法与路径 | 输入及结果 |
|---|---|
| `POST /api/question-banks` | `name`、可选`description`，必需1—128字符的`Idempotency-Key`。首次201，创建重放200；新库`revision=0` |
| `GET /api/question-banks` | `archived=false`默认只列未归档库，传true只列归档库；`limit`默认30、1—100，`afterId`为上页游标。返回`items/limit/nextAfterId` |
| `GET /api/question-banks/{bankId}` | 返回本人题库视图，归档库也可读；不存在或非本人统一404 |
| `PUT /api/question-banks/{bankId}` | 提交`name/description/archived/expectedRevision`整体设置元信息，说明省略时默认为空。成功200并递增修订 |
| `GET /api/question-banks/{bankId}/questions` | 同样使用`limit/afterId`游标；返回一致快照下的`bank/items/limit/nextAfterId`，保留不可用条目 |
| `PUT /api/question-banks/{bankId}/questions/{questionId}` | `questionVersionId/expectedRevision`，收录题目或把现有条目明确换为指定版本；成功200并递增修订 |
| `DELETE /api/question-banks/{bankId}/questions/{questionId}` | 查询参数`expectedRevision`，移除成员关系；成功200并递增修订，真正不存在的成员404且不消耗修订 |

名称原始长度1—120字符，服务端去除两端空白后仍须非空；说明最长2000字符。严格请求模型拒绝未知字段和错误类型。成员返回自身的 `id/questionId/questionVersionId/createdAt/updatedAt/available`；只有当前权限有效且题目和版本关系完整时，才附加白名单 `version` 和题目 `currentVersionId`。撤销授权或对应记录不可用时返回 `available=false`，不附加内容、当前指针或原作者身份。不可用成员仍参与稳定分页，不会因为过滤权限而从整理记录中悄悄消失。

成员读取在同一事务快照内取得题库修订、条目、题目和有效授权，分页期间仍可能有后续变更，这不是永久冻结的全库导出范围。成员中返回的具体版本可供后续选题界面组装原有来源字段；真正保存到问卷时仍走已有权限、来源、修订及内容匹配检查。本步没有新增绕过原保存链路的“直接写入问卷”接口。

| 状态和错误码 | 含义 |
|---|---|
| 401 `UNAUTHENTICATED` | 未登录或凭据失效 |
| 404 `NOT_FOUND` | 题库不属于本人，或收录题目不存在、不可读取 |
| 404 `QUESTION_VERSION_NOT_FOUND` | 指定版本不存在或不属于指定题目 |
| 404 `BANK_ITEM_NOT_FOUND` | 题库中没有要移除的成员 |
| 409 `IDEMPOTENCY_CONFLICT` | 同一创建键对应不同的初始题库内容 |
| 409 `BANK_CONFLICT` | 题库修订过期，或旧决定已不再是最后一次可恢复变更 |
| 409 `BANK_ARCHIVED` | 试图调整已归档题库的成员 |
| 422 `INVALID_REQUEST` | 字段、名称、类型、修订或分页参数不符合接口要求 |
| 503 `BANK_WRITE_OUTCOME_UNKNOWN` | 写入结果或写后恢复查询无法确认，应保留原请求和预期修订重试 |

存储契约错误及普通数据库不可用继续使用既有统一错误边界，不能把尚未开始写入时的普通读失败都描述成写入结果不明。

## 修订、重试与撤销竞争

每个题库只有一个递增的`revision`，元信息、收录、换版、移除均检查同一预期值；相关成员和题库修订在同一事务中提交。两次不同决定从同一修订出发时，只允许一方成功，另一方须重新读取确认。即使把条目再次设置为相同版本，使用新的预期修订也视为新的明确决定并递增；完全相同的原请求重放不递增。

创建采用永久身份：相同账号、相同创建键和相同规范化初始内容返回同一个题库。题库后续改名、归档或调整成员后，创建重放返回该库当前视图，不恢复最初名称、不回滚修订，也不创建第二份库。

后续变更采用有限重放：摘要同时绑定操作类型、题库、完整目标参数、题目及版本（若有）和预期修订。只有当前题库保存的最后摘要相同时，才能返回200并标记`Idempotent-Replay:true`。其后发生任何新变更，旧请求都不能再覆盖当前状态。例如移除后重新加入，再重试先前移除请求，应得到修订冲突，不能把重新加入的条目删掉。成功移除的重试先恢复最后摘要，不能仅因成员已被删除就误报404。各变更接口仅返回题库视图，避免为恢复结果再维护一份冗余成员快照。

收录或换版共享题时，只在事务中读到`active=true`还不够。成员写入事务还会真实递增对应有效授权的`useSequence`，与作者撤销修改同一授权文档形成写协调；成员写、题库CAS和授权序列共同提交或回滚。该字段表达依赖授权的写入顺序，扩展覆盖题库成员决定，不是问卷数、成员数或答卷数。已有条目的新决定仍须有当前权限，已经成功的原请求恢复则只返回本人题库元信息，不重新开放题目读取权。

MongoDB官方说明事务读取可能看到旧快照，实际修改同一文档会参与锁和写冲突处理；本步据此组织撤销与收录的顺序。[官方事务依据](https://www.mongodb.com/docs/manual/core/transactions-production-consideration/)。这些网页当前为9.0通用手册，本机目标为MongoDB 6.0.29副本集；资料是设计依据，不能替代本机竞争、重试、提交和回滚测试。受控事务钩子也不等同真实网络断开。

本轮实际覆盖以下范围：

1. 创建、永久幂等、创建键冲突、本人及归档列表分页、严格输入和接口白名单；第三方、未登录及题目接收者不能管理他人的题库。
2. 同库同系列去重、跨库复用、当前版本推进而成员固定不变、显式换版、移除与重加、归档及恢复；确认问卷来源、快照和历史答卷不被题库操作改变。
3. 全库CAS、跨操作摘要隔离、最后请求重放、后续变更后的旧请求拒绝；不存在成员删除不占修订。
4. 收录共享题、撤销后只保留不可用指针、不经题库新增使用权；撤销先提交与收录先提交两种顺序、授权写后失败时三处修改一并回滚。
5. 提交成功但服务返回丢失后的恢复、恢复查询自身失败时503；新增BSON约束及唯一索引，重复初始化和原七集合兼容、原问卷主干回归。

## 本步边界与AI记录

本步提供题库后端基础，没有题库管理或选题UI，也没有跨问卷统计；第七项整体要求须在题库选题界面接入并验收后再判定完成。没有迁移真实业务数据、按同名题自动建立成员关系、推送GitHub或提交课程平台。

主代理负责需求复核、模型取舍、后端接入和统一验证；测试代理编写题库测试，复核代理只读审查边界，文档代理依据实际代码及官方资料整理本文。此处如实记录AI分工，不将代码、测试或文档写作学生亲手产出，也不虚构用户已经掌握这些实现。主代理修正了首轮运行脚本地址遗漏及旧集合清单断言，并根据真实输出补入结果；没有把该修正写作用户亲手完成。
