# 修改题目前查看引用影响

记录日期：2026年10月27日。第一阶段基线99b66d1、本轮起点44432eb保留。本步补齐使用查询与实际修改决定之间的连接，旧`usages`接口及其权限不变。

## 任务书、理解与采用的边界

需求变更第六项要求“可以查看题目被哪些问卷使用”“修改时可以决定是否创建新版本”，反馈特别担心影响别人的问卷。第三项同时要求保护已发布内容。因此本步允许作者在保存或恢复前查看影响，选择创建新版本或取消；不以“不创建新版”为由覆盖任何已保存内容版本。取消检查保留本地编辑；取消编辑则放弃本页未保存内容。这个交互是对“是否”的实现解释，不是任务书指定的界面。

原使用查询只展示当前账号的问卷，不能因为已有相似列表就认定第六项已完整满足。本步另设作者专用影响查询：本人问卷显示标题，他人每份实际问卷显示稳定脱敏引用代号及本题引用数量。任务书未规定跨用户应显示哪些字段；采用代号是保护他人问卷的设计选择，不表示得到真实标题、所有者或打开管理页的权限。若课程验收明确要求他人真实标题，仍需另定授权边界，不能把当前代号称作真实名称。不会因已有题目使用权或统计授权而放宽问卷、答卷权限。

## 查询与数据库设计

新增作者专用`GET /api/questions/{qid}/impact`，可选questionVersionId；offset默认0、范围0—9007199254740991；limit默认20、范围1—100。返回questionId、questionVersionId、checkedAt、scope=saved_references、summary、items、offset、limit、nextOffset。错账号或不存在题返回404，错题版本404，未登录401，非法参数422。

summary分own与others，分别返回surveyCount、draftSurveyCount、draftInstanceCount、publishedSurveyCount、currentPublishedSurveyCount、currentPublishedInstanceCount、historicalSnapshotCount、historicalInstanceCount。surveyCount是至少有一类引用的去重问卷数；草稿、当前发布和历史可能重叠，不能直接相加。publishedSurveyCount是曾发布过的去重问卷数，历史数量是快照数。当前/历史按真实currentVersionId判断，关闭或截止不把当前发布版变成历史。

每个items元素对应一份仍存在的问卷，返回reference、ownership、草稿/当前发布实例数及历史快照/实例数；本人另有surveyId、surveyTitle、surveyStatus。他人不返回真实问卷ID、题目实例ID、标题、账号、公开链接、定义或答案。代号复用结构化HMAC，在question-impact命名空间隔离用途并截取20个十六进制字符，只是展示引用，不是访问凭据；轮换participant密钥可能改变代号。

来源只认服务器已保存的draftQuestionSources/questionSources，同题同版本条件在同一元素匹配。不按题干猜测关系；旧无来源题继续按原方式工作。作者查询真实引用不依赖当前共享active状态，撤销后留用的固定旧引用仍被计入；接收者不能调用作者专用入口。孤立发布快照因没有真实所属问卷不纳入。

不新增集合、登记表、业务字段或索引。聚合从surveys出发，按surveyId关联发布快照，只在MongoDB中分组引用元数据；再以同一个facet输入生成汇总和有界页。一次请求在现有snapshot事务内完成，数据库操作有20秒整体预算、聚合10秒限制。一致性概念参见[MongoDB snapshot读关注](https://www.mongodb.com/docs/v8.0/reference/read-concern-snapshot/)；链接为当前手册，实际聚合、事务和限制以本轮MongoDB6.0.29运行结果为准。没有读取responses或把全部来源/答案装入Python。现有surveyId索引支持逐卷关联，但入口仍遍历问卷候选；本步没有大规模性能或执行计划证明，不称为高效覆盖查询。若规模显示这成为瓶颈，应以实际计划评估索引或聚合改写，不先增加需同步的使用关系表。

这是实时偏移分页，每页请求有自己的快照；并发保存可能使跨页记录移动或重复，完整重查须从第一页开始。checkedAt是本次检查时间，不是冻结全局引用范围或保存锁，也不表示对端用户已同意换版。

## 保存与恢复的实际决定

作者点击“检查影响并保存新版本”或“恢复此版内容”后，父组件冻结题目、来源版本、预期当前头和待保存内容，先展示只读检查。界面默认按来源版本，也可查看整个系列，列检查时间、本人/他人计数和分页条目。读取失败不会显示成没有引用，也不能直接确认。

确认事件绑定本次决定、题目、来源版本与账号代际，确认后才创建现有幂等写请求。取消不会写入；本地内容在检查期间被锁定，异常变化会要求重新检查。保存冲突继续由原CAS保护；检查后他人新增引用不改变“已有引用仍固定旧版”的规则。已有未知写入只用原键和原请求重试，保存成功后回读失败只重读，不重复检查和派生。跨账号/题目/来源或卸载后的迟到响应失效。

## 实际验证

新增18项真实MongoDB/API定向全部通过，12.40秒；覆盖本人/他人、多实例/多版本、草稿解绑和换版、当前历史及关闭、共享撤销后保留引用、孤立快照/同名旧题排除、分页、错误参数、隐私字段和全部十二集合全文不变。另在真实保存提交夹入聚合之前的场景核对同一请求快照的一致性。

新增11项影响子组件、4项父组件决定保护用例；原派生/恢复的未知结果、冲突与成功回读用例保留断言，并补上明确确认步骤。最终整批前端204项通过、类型检查和构建通过。整批后端480通过、3项既有Windows符号链接权限跳过、251个子测试通过，198.01秒。演练脚本安全边界另有25项，已包含在480中，不相加。

真实浏览器从空合成库注册1账号，创建单选题V1、固定选题保存并发布1份问卷。检查显示本人去重1份、草稿1处、当前发布1处、历史0；取消后仍为V1且本地标题保留，审计成功写入仍只有原3次。重新检查并确认后生成V2，恢复V1前再次检查，确认形成V3；最终构建重新加载后核对“取消恢复”文案及取消不产生V4。最终5次成功审计写入。独立全文指纹核对十个受保护集合、原V1全文和题目稳定字段不变，草稿与发布仍固定V1。浏览器本轮是本人单选例，他人脱敏、撤销、分页和故障边界由API或受控组件测试覆盖，不冒称全部浏览器复演。
