## 原始要求与本步选择

本轮完整重读两份Word。需求变更第二项要求把题目共享给其他用户，让对方在自己的问卷中使用同一道题；它没有明确赋予接收者编辑、恢复或转授权权，也没有规定撤销后的处理和跨用户统计权限。第一阶段核心结构、旧功能和旧数据继续保留。评分为MongoDB设计35、后端逻辑25、测试10、文档15、AI使用说明15，因此本步先把可解释的权限关系、数据库约束与并发验证做实。

本项目选择按整个题目系列授权，接收者可读取过去及后续版本，并明确选择一个不可变版本加入自己的问卷。分享后续版本是设计选择，不是Word指定的唯一方案；接收者不会自动跟随题目当前指针换版。

撤销口径已经询问用户，用户明确选择“保留已有固定引用，禁止新增和换版”。下文按这一确认实现，不再将它写作尚未答复的假设。共享管理、题目使用权和答卷访问权分别判断，本步不等于共享题库、跨问卷统计或第二阶段全部完成，也不据此声称已经交付共享管理界面。

## 权限矩阵

所有入口要求登录，并逐次核对题目所有权或有效授权。不能只在列表或前端隐藏按钮，也不能凭知道ID取得权限。

| 操作 | 题目所有者 | 当前有效接收者 | 撤销后的原接收者 | 无关用户 |
|---|---|---|---|---|
| 读取独立题目、指定版本和版本历史 | 可以 | 可以 | 不可以 | 不可以 |
| 创建该系列的新版、恢复旧版 | 可以 | 不可以 | 不可以 | 不可以 |
| 授权、撤销、查看授权列表 | 可以 | 不可以 | 不可以 | 不可以 |
| 在本人问卷新增引用或更换固定版本 | 可以 | 可以 | 不可以 | 不可以 |
| 继续保存、发布服务器已经保存的同一固定绑定 | 可以 | 可以 | 可以，须满足下文的精确条件 | 不可以借此认领他人绑定 |
| 查询该题的使用情况 | 仅自己的问卷 | 仅自己的问卷 | 题目使用查询入口拒绝 | 拒绝 |

问卷统计、答卷明细和CSV仍由问卷所有者访问。题目作者不会因此看到接收者的问卷标题、使用明细或答卷；接收者也不会看到作者或其他接收者的问卷。撤销后独立题目、历史和使用查询返回404，但调用者仍可按原问卷权限读取自己的已存定义、发布快照和统计。

权限划分参考[OWASP授权建议](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)中的最小权限、默认拒绝及每次请求检查。这些是实现依据，不替代课程要求，也不把“可使用题目”扩大为“可管理题目或查看答卷”。

## 授权与读取接口

| 接口 | 用途与范围 |
|---|---|
| `PUT /api/questions/{questionId}/shares` | 所有者按接收用户名创建、启用或撤销授权 |
| `GET /api/questions/{questionId}/shares?limit=…&afterId=…` | 所有者分页读取该题授权记录 |
| `GET /api/shared-questions?limit=…&afterId=…` | 接收者分页读取当前有效的共享题目，条目采用题目视图 |
| 既有 `GET /api/questions/{questionId}`及版本列表、指定版本接口 | 在原所有者权限外，允许有效接收者读取 |

原创建、派生和恢复写入口仍仅属于题目所有者，没有接收者修改原系列或继续转授权的接口。本人题目与收到的共享题目分别读取，不把接收者改记为原题所有者。

首次授权示例；用户名为说明格式的占位值，不冒充真实账号或已执行请求：

```http
PUT /api/questions/<question-id>/shares
Authorization: Bearer <登录凭据>
Content-Type: application/json

{"recipientUsername":"<接收用户名>","active":true,"expectedRevision":0}
```

不存在授权时，`expectedRevision=0`且 `active=true`创建授权，成功返回201。后续变更必须携带已读取的修订，成功后授权 `revision`递增。撤销提交 `active=false`；重新启用也须基于当前修订作新的明确请求。

重试依据是该授权当前最后一次成功请求摘要。同请求成功重放返回200及 `Idempotent-Replay: true`，不重复改变状态；之后若已有另一状态变更，旧的激活请求返回冲突，不能借旧请求把已撤销授权复活。它不是永久保存全部请求历史的恢复接口，调用者应保留原请求，并在冲突时重新读取当前授权再决定。

| HTTP与错误码 | 含义 |
|---|---|
| 401 `UNAUTHENTICATED` | 未登录或凭据失效 |
| 404 `NOT_FOUND` | 题目不存在或不具备该入口所需权限 |
| 422 `INVALID_USERNAME` | 接收用户名不符合现有账号规则 |
| 404 `RECIPIENT_NOT_FOUND` | 接收账号不存在 |
| 422 `INVALID_SHARE_RECIPIENT` | 试图把题目共享给自己 |
| 404 `SHARE_NOT_FOUND` | 不存在授权时尝试撤销 |
| 409 `QUESTION_SHARE_CONFLICT` | 授权修订过期，或旧请求不再是可重放的最后请求 |
| 422 `INVALID_REQUEST` | 字段、类型或分页参数不符合契约 |
| 503 `QUESTION_SHARE_WRITE_OUTCOME_UNKNOWN` | 写入结果无法确认，应保留原请求重试 |

本轮API测试已核对正常状态、模型、权限及修订冲突；新增共享写入的不明结果和恢复查询失败尚未做故障注入，不把这些错误分支写成已实测。

## 撤销后的精确边界

保留资格只来自服务器当前已保存草稿里的同一组 `surveyId/instanceId/questionId/questionVersionId`，并且问卷属于当前调用者。客户端重新提交一段来源数组，不能自行证明这是旧绑定；服务端必须读取已保存关系进行比对，内容匹配和原问卷校验继续执行。

例如接收者已把题目V1保存到问卷A的实例q1，之后作者撤销授权：A仍可按这个绑定修改卷内必答或跳转、保存并发布；不能换成题目V2，不能把同版V1加为q2，不能复制到新问卷B。即使两个版本内容相同，更换版本ID仍属于换版，需要当前有效授权。

明确解绑并保存后，该实例失去保留资格；之后不能借旧发布快照或相同题干重新绑定。未保存的本地编辑不是服务器既有绑定，历史复制若恢复了当前草稿已不具有的来源，也不能绕过撤销。已发布快照、旧填写凭据及历史答卷保持原义，不删除来源或改写旧答案来实现撤销。

## MongoDB关系、并发与兼容

新增独立集合 `question_shares`，不把所有接收者嵌进题目主文档：

| 字段 | 含义 |
|---|---|
| `_id/questionId/ownerId/recipientId` | 授权身份、所属题目和双方账号关系 |
| `permission/versionScope` | 本步固定为 `use/series`，明确只授予系列使用权 |
| `active/revision` | 当前有效状态及授权管理的比较修订 |
| `useSequence` | 新引用获取授权时实际递增的协调字段，不是问卷数或答卷数 |
| `requestDigest` | 当前最后一次成功授权请求的摘要，用于有限成功重放 |
| `createdAt/updatedAt/schemaVersion` | 记录时间及文档格式标记 |

唯一索引 `(questionId, recipientId)`保证同题同接收者只有一条授权；另为所有者授权列表和接收者有效列表建立相应索引。BSON校验器约束文档形状及字段类型，题目归属、接收账号存在性和跨集合权限由后端核实。

新引用不能只在事务开始时读一次 `active=true`就继续写问卷。事务快照可能读到撤销前状态，因此新增共享引用在保存事务内真实递增对应授权的 `useSequence`，与撤销修改同一授权文档发生写协调；失败时授权计数和草稿都应回滚。题目所有者使用自己的题目不需要授权记录，精确保留的旧绑定也按已确认的兼容规则判断。

显式提交来源的草稿保存进入事务，`Repository.save_draft`增加可选session，使来源验证与原草稿修订更新处于同一事务；普通无来源旧保存继续沿用原逻辑。发布仍重新校验可信来源，保留服务器既有绑定资格，不让撤销悄悄破坏已保存问卷。

MongoDB说明了[事务快照可能陈旧及实际更新获取写锁](https://www.mongodb.com/docs/manual/core/transactions-production-consideration/)，也建议在[更新条件中包含预期当前值](https://www.mongodb.com/docs/manual/core/write-operations-atomicity/)。本步据此组织授权状态和新引用的竞争。这是设计依据；当前在线手册为9.0通用说明，具体提交、冲突与重试仍须在本机MongoDB 6.0.29副本集实际验证，不能由引用文档替代实测。

原六集合的schema及来源三字段保持，不回填旧题、问卷或答卷，不按相同内容推断共享身份，原 `schemaVersion`含义不变。初始化只新增授权集合、约束和索引，不迁移真实业务数据。兼容是新程序继续处理旧格式，不等于第一阶段旧程序已经懂得授权语义；回退程序前仍需停止相关写入并单独核对。

## 验收计划、结果与AI记录

本轮使用隔离副本集、随机测试库和合成账号。验收应同时检查响应、权限及数据库状态：

1. 作者授权后，接收者能读取过去及后来创建的版本；将同一题的指定版加入自己的问卷并发布。第三方、未登录用户及接收者编辑、恢复、转授权均拒绝。
2. 核对本人和共享列表、授权列表的分页与白名单；作者和接收者的使用查询只返回各自问卷，统计、明细、CSV不能因共享越权。
3. 既有精确绑定在撤销后可保存和发布；新实例、新问卷、换版、相同内容换版、解绑后重绑和历史复制不能绕过撤销。旧快照、旧填写和答卷仍按原版工作。
4. 验证首次授权、撤销、重启用、同请求重放、过期修订和后续变更后的旧激活请求；失败不得占用成功修订或复活授权。
5. 在真实MongoDB事务中同步控制新增引用与撤销的先后，核对实际写冲突、重试及唯一合法结果；覆盖保存/发布失败回滚、未知结果及恢复查询故障，不把受控故障写成真实断网。
6. 检查新增集合约束、唯一索引、旧六集合约束与业务全文，回归私有题、来源保存、发布、填写、统计、使用查询和恢复；核实测试库及专用进程归属后清理。
