# 跨问卷单题统计与汇总授权

核对日期：2026年10月27日。本文对应本轮代码中的 `question_statistics.py`、`question_statistics_api.py`、`QuestionStatistics.vue`、`QuestionStatisticsGrantPanel.vue` 及统计回归测试。字段清单以 [数据库说明](schema.md)、[接口说明](api.md) 和 [OpenAPI](api-openapi.json) 为准；需求背景见 [需求说明](requirements.md)。本文说明统计口径、数据库取舍、权限和恢复边界。

## 本轮解决的问题

已有统计以一份问卷的一个发布版本为入口，不能据此认定已满足“跨问卷统计同一道题”。本轮以独立题目 `questionId` 为入口，从服务器保存的发布来源中找到对应实例，再按不可变的 `questionVersionId` 分别汇总。数值题提供总体分布、合计、平均、最小和最大值；单选和多选按固定版本的选项统计；文本只在汇总中给出计数。

权限采用用户在本轮明确选择的规则：本人问卷直接纳入；其他问卷须由其所有者单独授权给题目作者，且只提供汇总。题目使用共享与答卷统计授权是两项不同决定，前者不授予后者。这个权限方案以及30分钟范围、7天回执、导出上限均为本项目的实现决定，不将它们表述为任务书原文。

本轮继续使用第一阶段的发布快照、提交序号、路径、答案和事务边界，不改写已有答卷，也不另存一份答案仓库。第一阶段基线仍为 `99b66d1e637fa3b4ecb13719c0230ecb7e958701`；本轮代码是其后的增量扩展。

## 哪些发布内容进入统计

来源必须是 `survey_versions.questionSources` 中明确保存的关联：题目系列、题目版本和卷内实例三者一并核对。服务还检查实例存在、版本确实属于该系列，以及实例的题型、题干、配置与不可变题目版本一致；发现破坏来源约束的数据时报 `DATA_INVARIANT`，不按相似标题猜测。

范围包含有权限的问卷中所有符合筛选的历史发布版本，既包括当前版，也包括被后续发布替代的版本。问卷关闭或截止不删除其已接收答卷的统计意义。只在草稿中引用的题目尚无发布来源，不进入统计；草稿解除引用也不抹掉旧发布来源。没有 `questionSources` 的第一阶段旧发布内容照常支持原有功能，但不会自动归入某个独立题目。即使题型、题干和选项完全相同，也不能据此补造来源。

题目版本筛选为空时，取系列内全部符合条件的版本并分别展示；指定版本时，只取该版本的实例。`respondentType` 可选全部、匿名或实名答卷。这里“实名”沿用提交时的匿名标记，只用于计数和筛选；跨问卷明细接口仍不返回答题者身份。

## 先固定范围，再读取结果

用户点击“获取新范围”时，服务器在同一个快照事务中确定可用发布来源，并读取每份问卷自己的 `submitSequence`。每个来源保存对应的 `surveyVersionId` 和 `asOfSeq`。随后汇总、来源列表、本人明细和CSV都必须使用同一个 `scopeId`，并分别限制 `acceptedSeq <= asOfSeq`。

提交序号只能在同一份问卷内比较。例如范围捕获时A截至3、B截至2，B后来接收的序号3不能因为小于等于A的3而混入结果。已接受答卷和发布快照沿用不可变约束，后续新增答卷、新发布版本和新授权来源不会自动扩张原范围。用户明确刷新后才会得到新的来源和序号上界。

范围有效30分钟。服务每次读取都核对账号、题目、到期时间、来源数、问卷归属和汇总授权修订；不能依靠TTL后台删除来判断是否仍有效。授权或归属变化使原范围失效时返回409，范围不存在或到期时返回410。界面清除旧结果并要求明确获取新范围，避免把旧数据继续显示成当前结果。

每次查询使用各自的快照事务检查权限。撤销提交后发起的后续查询会重新检查并拒绝旧范围；已经在撤销前取得快照并执行中的读取不承诺被即时取消。已经看到、截图或保存的汇总也无法收回。这与问卷保存等写入操作使用共享授权序列协调写竞争的机制不同，不能把本轮读取权限描述成对在途读取加锁。

## 三个新增集合

| 集合 | 保存内容与用途 | 关键约束及保留期 |
|---|---|---|
| `question_stat_scopes` | 范围拥有者、题目和筛选、创建键与摘要、创建/失效时间及来源数量 | `(viewerId, creationKey)` 唯一；业务有效30分钟；`purgeAt` 为创建后7天，并有TTL索引 |
| `question_stat_sources` | 每个范围包含的发布版本、问卷独立序号上界、本人或汇总权限模式；汇总模式另存授权ID及修订 | `(scopeId, surveyVersionId)` 唯一；`(scopeId, _id)` 支持来源分页；`expiresAt` TTL为范围到期时间 |
| `question_stat_grants` | 问卷所有者向题目作者提供汇总的独立授权、当前状态、修订及最后操作摘要 | `(surveyId, questionId)` 唯一；接收查询有 `(questionId, recipientId, active)` 索引；撤销保留记录和递增修订 |

范围根记录与子来源在一个事务中写入。来源按发布版本拆成独立文档，避免把无限增长的来源数组塞入一个根文档。元数据不保存原始答案、文本内容、填写者身份或一份发布定义副本。授权模式由集合校验约束：本人来源不带授权字段，汇总来源必须带授权ID和修订。三集合均有严格结构校验；初始化增加它们的校验与索引，不回填旧业务文档。

30分钟到期限制可用数据范围，7天保留限制创建请求的恢复窗口，两者用途不同。源文档到期可先被清理，根回执仍能识别旧创建键并返回“原范围已过期”。TTL清理由后台执行，实际物理删除可能晚于到期；权限有效期由应用判断。超过7天且回执已被清除后，不保证同一旧键永久指向原范围。界面超过本地30分钟恢复窗口时会要求明确结束原操作，不能偷偷换键重发。[MongoDB TTL说明](https://www.mongodb.com/docs/manual/core/index-ttl/)解释了这类索引的后台过期清理机制。

## 计数单位与四类题型

统计单位有三层：发布来源、来源答卷、题目实例的一次作答机会。不能把实例作答次数直接写成人数。

对某个题目版本在一个发布来源中的实例集合记为I。对范围内该来源的每份答卷：

| 字段 | 对每份答卷计算的值 | 业务含义 |
|---|---|---|
| R | I的元素数 | 作答机会，包含被跳过的实例 |
| V | I与path交集的元素数 | 路径经过的实例数 |
| A | I与answers.questionId交集的元素数 | 存在有效答案的实例数 |
| U | I与path交集再扣除answers.questionId后的元素数 | 经过但未作答的实例数 |
| S | I扣除path后的元素数 | 路径未经过的实例数 |

各来源求和后必须满足 `R = A + U + S`、`V = A + U` 和 `0 <= A <= V <= R`。同题在一份问卷中出现两次会形成两次机会；问卷自己定义的必答、可选和跳转仍由各实例独立决定。

`responseCount` 是相应发布来源中的答卷数，包括没有走到该题的答卷；`answeredResponseCount` 是至少给相应实例集合提供过一次有效答案的答卷数。同一答卷对同版本两个实例作答，A增加2，至少作答的答卷数增加1。系列概览也按答卷去重，同一答卷同时使用V1和V2时概览只计一次，所以不能简单相加各版本的答卷数。

| 题型 | 汇总口径 |
|---|---|
| 数值 | 每次有效实例答案进入合计；平均为跨来源总和除以A，不能平均各问卷平均值；零是有效值；无答案时平均/最小/最大为 `null` |
| 数值分布 | 按该版本全部有效数值的最小至最大范围划分最多10组；组间左闭右开，末组含最大值；全相同时为一个点值组，无答案为空数组；计数之和必须等于A |
| 单选 | 按固定版本的选项ID计数，列出零次选项；选项百分比以A为分母，总选择次数必须等于A |
| 多选 | 每次有效实例答案中的每个已选选项分别计一次；百分比仍以A为分母，所以各选项百分比之和可以超过100%；另给总选择次数 |
| 文本 | 汇总只给作答与路径计数；不把文本数组或文本样本混进汇总。本人来源的原文可通过明细读取 |

不同题目版本分别计算和展示。题干、选项、量纲、范围或含义可能已改变，本轮没有给不同版本建立可合并的映射，不输出跨版本总平均值或总分布。每份问卷的参与标识又使用问卷范围内的保护方式，不能用于跨问卷识别同一人；本轮没有“跨问卷唯一人数”。

## 查询实现与资源边界

服务在一个请求的事务会话内依次处理固定发布来源。每个来源先按问卷ID、发布版本及序号上界限制答卷，MongoDB再用集合交并差、`$group`、`$unwind` 和分面聚合计算计数及有限的数值或选项结果。Python合并的是计数、数值摘要和来源元数据，没有先把全部答卷或全部文本载入Python再统计。数值分布在得到同版本全局最小和最大值后，再用统一边界进行第二次数据库分组，保证不同问卷的分布可以相加。

本轮没有在事务中使用 `$unionWith`，也没有为每个来源分别调用原单卷统计、在不同事务中拼接结果。MongoDB列出的事务聚合限制包含 `$unionWith`；PyMongo事务回调可能重试，同一会话中的操作应顺序执行。因此范围写入没有外部副作用，同一请求中的数据库操作保持顺序。[事务允许的操作](https://www.mongodb.com/docs/manual/core/transactions-operations/)、[PyMongo事务说明](https://www.mongodb.com/docs/languages/python/pymongo-driver/current/crud/transactions/)。

沿用仓储事务的 `snapshot` 读关注、`majority` 写关注、主节点读和默认20秒整体数据库操作时限；具体聚合另设时间限制。每个发布来源受已有每卷题目数和选项数限制，分面只返回分组结果，不构造原始答案大数组。但这不代表系统容量已被证明：当前仍会载入全部符合权限的发布来源元数据、校验关联版本，并遍历来源；汇总版本分页只限制返回页，不代表只计算当前页。大规模来源数量、极多历史版本和大量答卷的延迟、内存与查询计划尚未做专项基准。

`$facet` 本身也有内存与最终BSON大小限制，不能因设置 `allowDiskUse` 就宣称可以任意扩大。本轮按有限结果组织聚合，仍保留超时和失败边界，未把功能回归当成性能证明。[MongoDB分面聚合限制](https://www.mongodb.com/docs/manual/reference/operator/aggregation/facet/)。本轮实际运行环境为MongoDB 6.0.29与PyMongo 4.19.0，官方链接是当前手册，不能由当前手册推导本项目已验证分片或其他服务器版本。

## 七个接口与读取边界

所有接口均要求登录，路径均在 `/api` 下。下表列出职责；完整字段和参数上限见接口主文档。

| 方法与路径 | 职责 |
|---|---|
| `POST /questions/{qid}/statistics/scopes` | 用 `Idempotency-Key` 创建固定来源范围；首次201，恢复原结果200；请求包含版本和答卷类型筛选 |
| `GET /questions/{qid}/statistics` | 按 `scopeId` 读取系列概览和分版本汇总；版本按 `versionNo` 升序，使用 `afterVersionNo` 分页 |
| `GET /questions/{qid}/statistics/sources` | 读取固定发布来源；按来源ID及 `afterId` 分页 |
| `GET /questions/{qid}/statistics/answers` | 读取范围内本人问卷中该题的有效实例答案；可按范围内版本筛选，使用签名游标分页 |
| `GET /questions/{qid}/statistics/export` | 导出同一范围和版本筛选下的本人明细CSV |
| `GET /surveys/{sid}/question-statistics-grants` | 问卷所有者读取真实发布来源中出现过的他人题目及授权现状 |
| `PUT /surveys/{sid}/question-statistics-grants/{qid}` | 问卷所有者以 `expectedRevision` 明确授权或撤销汇总；返回200，原请求恢复另带重放标记 |

来源列表对本人问卷返回实际问卷标题与定位ID；他人汇总来源使用“已获授权的其他问卷”，不返回真实问卷标题、问卷ID或发布ID。授权对象固定为该题目的实际作者，客户端不能指定任意接收账号，也不能向未在本卷发布过的题目授予权限。

本人明细的一行表示某个实例的一次有效答案，返回其问卷、版本、实例、回执、提交序号、提交时间、匿名标记及本题值。它不返回答题者身份、保护标识或其他题目的答案。混合了他人汇总来源时，汇总A通常大于本人明细行数；接口 `coverage` 和界面均明确说明此差异。仅有他人汇总来源时，本人明细和CSV可以合法为空，不能为凑齐汇总数量而泄露原始答案。

明细按来源ID、来源内提交序号和实例ID排序。游标签名绑定账号、范围和版本筛选，换范围、换筛选或篡改不能继续翻页。版本不存在或不属于当前题目返回404；已经固定单版范围却试图读别的版本返回422。分页不使用可因新答卷插入而漂移的全局偏移。

CSV使用UTF-8 BOM，最多20,000条实例作答且总内容不超过8MiB，字节限制包含BOM。服务按每批100行读取，在返回前检查完整导出大小，超限明确返回 `EXPORT_TOO_LARGE`，不截断后宣称成功。导出保留题目版本和实例，选择题值沿用选项ID，多选以分隔符连接；界面可用已知版本的选项标签显示明细。文本和标题可能形成表格公式时，在导出单元格前加单引号，存储答案不受影响。

## 创建、授权与界面的恢复方式

范围创建键按账号唯一，摘要绑定题目、指定版本和答卷类型。相同键和相同请求恢复同一范围，不重新捕获新增答卷；相同键但筛选不同返回409 `IDEMPOTENCY_CONFLICT`。写入异常后先按持久回执恢复：能找到已提交结果时返回原范围，确认不到时给出 `STATISTICS_SCOPE_WRITE_OUTCOME_UNKNOWN`。部分插入失败时根和来源共同回滚。不能把收到503直接解释为数据库一定没有保存。

授权用预期修订比较并递增，同一问卷和题目只保存一份记录。最后操作摘要允许原请求有限重放；后续已有新决定时，旧激活或旧撤销不能覆盖新状态。撤销保留记录，重新授权递增修订；旧范围记录的授权修订不会随重授复活，必须获取新范围。若写入结果或恢复读取不能确认，返回 `STATISTICS_GRANT_WRITE_OUTCOME_UNKNOWN`，保留原请求继续核对。

统计界面冻结未确认创建操作的键和筛选。POST结果未知时只提供原请求重试；创建已成功但汇总、来源或明细读取失败时只重新执行GET。读取失败不会悄悄再创建一个更晚的范围。修改筛选时界面仍用已固定范围的标签解释旧结果，明确刷新后才应用新筛选；明细筛选改变后也须重新读取，未应用前禁用导出。

授权界面先展示题目作者和实际影响，用户明确确认后写入。未知结果保留目标、开关和原预期修订；已保存但回读失败只读回状态；修订冲突要求读取当前状态并重新决定，不能自动换用新修订把旧意图再次提交。统计页与授权面板均保护未完成操作的离开、切换和注销入口；旧账号、旧题目或已卸载组件的迟到响应不能覆盖新页面。401按登录失效处理，409/410统计范围问题不冒充登录失效。

## 兼容、回退与未完成的验证

本轮增加三集合及服务和界面，复用原答卷与发布结构，没有要求用户迁移已有答案。第一阶段未记录独立来源的数据不自动归类，是保留真实数据来源的兼容选择，并非迁移遗漏。不能通过扫描相同题干来伪造“跨问卷历史数据已经迁移”。

原单卷统计、填写、提交、编辑、发布及题库和共享流程继续走各自既有接口和权限，统计授权不放宽它们。旧业务文档不因创建范围或授予汇总而被重写；数据库初始化和既有约束仍由回归测试核对。保留Git基线及变更记录支持追溯，本轮没有执行对真实运行库的升级或回退演练，也没有自动删除新集合、推送GitHub或提交课程平台。完整升级与回退仍须以备份和隔离副本实测，不能仅凭旧文档仍在就标记完成。

## 实际验证与AI记录

本轮统计测试使用真实ASGI应用与MongoDB隔离数据库，通过注册、保存来源、发布和提交接口构造数据；没有用标题相似的伪来源或模拟成功存储来替代链路。故障测试只在明确的测试钩子和驱动边界注入异常，不能称为真实网络断线试验。

已完成的统计定向结果为 **30项通过，22.73秒，0失败**。其中19个测试函数经参数化形成30项，主要覆盖：

- 两份问卷三个实例、可选和分支的金样：`R=8, V=6, A=5, U=1, S=2, sum=100, avg=20`，来源答卷5份、至少作答4份；数值零正常计入。
- 各问卷分别固定序号，B后来收到的序号3不混入B截至2的范围；捕获事务期间真实提交以及重新发布后，旧范围保持原结果，显式刷新才扩大。
- 同答卷同时引用V1和V2，分版本统计分别解释，系列概览不重复计数；空、零、常量和窄幅大数直方图；单选、多选零次选项与百分比；文本汇总不含原文，CSV转义。
- 同名不同题、旧无来源发布、仅草稿引用排除；本人历史、分页完整性、游标绑定与篡改、范围幂等和过期、严格集合校验及TTL索引。
- 独立汇总授权、撤销、重授和原范围失效；他人原始答案与身份不经明细或CSV返回；事务回滚、真实提交后回执恢复、同修订并发授权的单一胜者。

首轮为9失败、17通过：七项因共用金样夹具给单选规则写了不支持的运算符，另两项分别为旧统计请求缺少必需的发布版本参数，以及文本已被既有提交逻辑去除首尾空白而测试预期未同步。第二轮改成的单选运算符仍不符合领域协议，结果7失败、22通过；核对 `domain.py` 后改用实际规定的 `eqOption`。随后保留原金样目的，补充真实事务恢复、并发和重新发布用例，再得到30项通过。这里如实保留夹具修正过程，不把前两轮写成通过，也不把这些夹具错误描述为已发现并修复的业务缺陷。

本轮完整后端结果为 **437项通过、3项跳过、251个子测试通过，195.58秒，0失败**。三项跳过沿用Windows符号链接创建权限限制，不等于相关平台场景已通过。补齐父页面导航保护后，最终整批前端 **189项通过，4.03秒，0失败/跳过**，类型检查和生产构建通过。前端用例执行实际Vue setup和响应式逻辑、控制HTTP返回，没有挂载DOM；真实浏览器另行验证。汇总见[本轮结果](evidence/phase2-question-statistics-results-20261027.json)及[测试摘要](evidence/phase2-question-statistics-tests-20261027.txt)。

真实浏览器从空的独立合成库开始，注册两个临时账号，在题目管理创建数字题V1（0—100整数），由作者共享给接收者。A、B分别通过本人/共享题目选择器固定V1，保存、发布并真实匿名提交0和3。没有预先播种业务数据。新构建的统计页显示两问卷、两答卷，R/V/A均为2、U/S均为0、总和3、平均1.5、最小0、最大3，直方图总计2；本人明细只显示A的0，B只显示概括授权来源。

接收者先取消授权，再确认授权，实际仅产生一次授权PUT、修订1；随后确认撤销为修订2。作者重新进入后明确获取新范围，只纳入A，A=1、sum=0、avg=0，本人零值仍在。将选择器改成实名后，界面保留原范围的全部答卷标签并提示尚未应用；明确刷新后显示0份实名答卷、空明细和无均值，随后再显式刷新回全部答卷。最终共4个范围、5条固定来源、1条inactive授权、14次审计成功写入。按精确数据库归属验证后，通过独立读取实际存储数据重新计算上述四个范围，结果与页面一致。见[成功写入审计](evidence/phase2-question-statistics-browser-20261027.json)。

本轮浏览器使用同题V1和数字题；多版本、其他三类题、旧范围在撤销后的读取拒绝、未知结果等由真实后端或受控组件用例覆盖，未声称全部在浏览器复演。CSV按钮已点击且无可见错误，但本轮未独立检查浏览器下载文件内容；CSV内容和本人覆盖边界由后端测试核对。原始截图只保留在私有本地目录。最后复核另补了问卷固定引用栏的统计入口，撤销使用共享后仍可从旧引用进入本人的历史统计，往返保留未保存草稿；最后入口以新增父页面状态用例和最终构建验证，未再次浏览器点击。浏览器证据对应入口补充之前的统计/授权界面构建。没有由功能测试推断性能、分片、跨版本数值可合并或真实数据升级已验证。清理与原项目保护见[收尾记录](evidence/phase2-question-statistics-shutdown-20261027.json)。
