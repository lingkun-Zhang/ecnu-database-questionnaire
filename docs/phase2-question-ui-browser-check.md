本轮使用临时空数据库，没有预置账号、题目、问卷或答卷。主代理通过Cua操作真实构建页面和后端，注册合成账号并逐步完成下列流程；这些是AI浏览器操作，不记作学生人工演示。产品前端、后端及数据库结构没有修改，代码修改仅涉及浏览器审计工具和它的定向测试。

## 换版后，旧填写与另一份问卷仍使用原版

先在个人题目页面建立数字题V1，范围为0—7，且只接受整数。创建问卷A、B，各自明确选择题目V1，保存草稿并发布；A通过收集设置开启多次填写，以便在同一账号下分别核对新旧发布版。

在一个标签页开始填写A，保留这次取得的问卷V1，再回到管理页面将题目派生为V2，范围改为1—5。仅在A中显式选择题目V2、保存并发布为问卷V2；B没有换版。这里“题目版本”与“问卷发布版本”是两种编号，不能仅凭都叫V1/V2就视为同一实体。

| 浏览器操作 | 实际结果 |
|---|---|
| 回到之前已开始的A旧填写标签页，填写0并提交 | 成功取得回执，属于问卷A的发布V1 |
| 重新开始填写A，填0后点击继续 | 显示“数字超出允许范围”，无法进入提交步骤 |
| 将新A的答案改为3并提交 | 成功取得回执，属于问卷A的发布V2 |
| 打开B，填写0并提交 | 成功取得回执，仍属于问卷B的发布V1 |

新A对0的拒绝发生在填写求值及继续步骤，本轮没有将0发到提交接口取得POST拒绝响应。该观察证明页面按新版本约束阻止继续，不能扩大为本轮重新验证了服务端提交拒绝分支；该分支的后端结果仍应引用此前对应批次。

随后通过管理界面的逐版统计及原始回答明细核对：

| 问卷发布版 | 其中固定的题目版 | 答卷数 | 明细中的数字 | 总和 | 均值 |
|---|---|---:|---:|---:|---:|
| A的V1 | 题目V1 | 1 | 0 | 0 | 0 |
| A的V2 | 题目V2 | 1 | 3 | 3 | 3 |
| B的V1 | 题目V1 | 1 | 0 | 0 | 0 |

旧填写成功、B保持原约束与逐版结果同时说明了本次操作的隔离效果。这里只报告这组三份答卷，不据此声称已穷尽所有竞争调度、填写政策或统计组合。

## 只解除来源，也能保存并独立编辑

回到A的当前草稿，只点击“解除引用”，不改变题目内容。保存按钮立即可用；保存后草稿修订为r3。重新打开A，来源提示消失，题目内容控件恢复可编辑，范围仍为1—5；卷内实例ID、必答与默认去向保留。

这次解绑只影响草稿，没有再次发布。随后在个人题目的使用情况界面分别查询，得到下列结果：

| 查询范围 | 浏览器显示 |
|---|---|
| 当前草稿、整个题目系列 | 只有B |
| 发布快照、整个题目系列 | A的V1、A的V2、B的V1，共三条发布记录 |
| 发布快照、题目V2 | 只有A的发布V2 |
| 当前草稿、题目V2 | 没有使用记录 |

A草稿仍有同样题干和1—5配置，但解绑后不再出现在来源查询中；A旧发布记录继续出现。查询依赖保存的明确来源关系，不能按内容相似把已解绑草稿重新算作题目使用，也不能把三条发布记录写成三份不同问卷。

## 审计工具发现的问题与修正

核对辅助审计时发现，原工具用 `type(value) in (int, float)`筛选数字，排除了MongoDB读出的BSON `Int64`。因此本轮原始审计中的整数答案列表可能为空；应用统计与明细已正确显示0和3，这个遗漏属于证据工具，不是答案未入库或产品统计错误。

测试代理将筛选提取为 `numeric_answers`，接受整数、浮点数及BSON整数，同时明确排除布尔值、数字字符串、空值和非数字题。新增纯测试覆盖0、3、小数、安全字段输出和不改写输入答卷，共14项通过、0失败，0.41秒。它们不启动应用、不读取真实配置、不访问数据库，不能当作新增14项真实数据库或浏览器测试。

本轮浏览器服务从启动到结束均加载旧工具。原始审计保留，不用修复后的逻辑重写已发生的事件。主代理按私有归属清单、精确owner标记及专用实例确认临时库，再用修复后的 `safe_summary`以只读事务生成补充快照。补充快照真实读得A的两个发布版数值分别为0、3，B为0；除已说明的整数遗漏外，其余安全快照内容与原始最终审计相同。

本轮没有重跑前端95项或后端310项全量回归；这些计数仍属于此前批次，不能与本次14项工具测试相加成一个新的全量结果。
