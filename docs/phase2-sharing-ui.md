# 共享题目管理与选用界面

记录日期：2026年10月26日。从本地提交 `860e07c` 的[共享后端](phase2-question-sharing.md)继续，本步接入界面，不新增后端业务接口或数据结构。第一阶段基线仍为 `99b66d1e637fa3b4ecb13719c0230ecb7e958701`。

## 本步行为

侧栏统一称“题目管理”。“我的题目”可以创建内容、查看历史、派生、恢复、查询本人使用情况，并按用户名授权他人使用；“共享给我的”只读，可以查看版本并在自己的问卷中选择具体版本。可读题目不等于作者身份：只有来自本人列表的当前选中题目显示编辑、恢复和共享管理。

共享管理显示当前接收者、状态和授权修订，支持新增授权、撤销及重新启用。撤销和重新启用先显示页内确认，冻结原接收者与修订；取消不发送写请求。确认期间锁定其他授权决定，切题、换账号或卸载后不能提交旧确认。共享只授予题目使用权，不授予编辑、恢复、转授权或他人问卷和答卷访问权；后端继续作为权限依据。

问卷编辑器改称“从已保存题目选用”，可以在本人和共享列表中选题。先明确选择题目版本，再固定其内容；本卷必答和跳转仍由本卷设置。查看或换版时锁定到现有题目系列，不能把可读共享题当成自己的题目编辑。

撤销口径来自用户已确认的选择：服务器当前草稿中已有的精确固定引用可以继续保存、发布和填写；新增实例、新问卷和换版需要有效授权。界面在撤销后查不到来源时清空旧候选和历史，并说明已保存引用可保留，关闭窗口不会解绑。新选题、历史或使用查询遇到404也清除不可继续选择的缓存，避免用旧界面状态选入已不可用版本。解绑并保存后，原来的保留资格不再存在。

本人题目沿用偏移分页；共享题目和授权列表使用服务器返回的游标，不根据一页是否满额猜测下一页。切换列表会清空旧选择、历史和编辑内容。父页面把共享请求纳入忙碌与未保存保护，防止等待期间切页或误退出；迟到响应同时核对账号、题目、请求代次和组件存活状态。

## 写入失败与修订冲突

网络结果不明或503时保留原始请求体，只允许原请求重试，不能悄悄更换接收人、目标状态或预期修订。PUT已成功但回读失败时只重试GET，不再次改变授权。

409不自动套用新修订重发。先读取当前列表，允许翻页找到接收者，展示原决定与服务器状态；已有接收者身份必须相同。显式核对后才能以读到的修订提交。若服务器状态已是目标状态，结束待处理决定而不再写入。首次授权时尚无接收者ID，必须由操作者明确确认当前账号行，不用客户端转小写逻辑代替后端用户名规则。冲突核对、放弃和离开保护仍使用浏览器原生确认，这些分支本轮只做受控组件测试。

真实浏览器从空的独立数据库开始，所有合成账号、题目和问卷由页面创建，没有预置业务记录：

1. 作者创建数字题V1，范围0—7、只接受整数，授权另一账号；再派生范围1—5的V2。接收者看见历史和当前V2，界面无编辑、恢复或转授权入口。
2. 接收者给问卷A明确选V1，保存r1并发布。作者查询本人使用情况为空，不展示接收者的A。
3. 作者撤销后，接收者原来源窗口不可选择缓存版本；关闭窗口仍保留原引用。A只改说明后保存r2、发布第二版，并实际填写0成功，仍按旧题V1解释。
4. 接收者新建B，撤销期间共享选择列表为空，保存空草稿r1。作者重新启用的页内确认先取消，修订不变；再确认启用、撤销和启用，最终修订5、有效状态true。
5. 接收者重新打开B，选择题V2，保存r2并发布第一版。页面与只读数据库核对范围为1—5；B本轮未填写，不虚构新版答卷。

第一轮原生确认工具返回不稳定，撤销结果曾暂时无法确认。重新读取真实状态后证实只发生一次撤销，修订从1到2；没有把工具超时当作服务拒绝或重复撤销。随后将常规撤销/启用改为页内确认，重新完成类型检查、构建、全量前端测试和上述取消/确认流程。数据库观察到的授权写入修订恰为1、2、3、4、5，取消未产生额外写入。

最终为2个合成账号、1题、2个题目版本、2份问卷、3个发布快照、1份答卷、1条授权。共有15次被白名单观察到的成功业务写入。只读事务核对A草稿及两次发布始终引用V1、第二次发布所收答卷的数值为0，B草稿及发布引用V2，授权useSequence为2；账号归属和末次审计一致。没有把安全摘要比较写成所有集合全文未变。

本轮真实浏览器未注入断网、409或迟到响应，也未跨页造数据；这些边界由受控前端测试覆盖。其余三种题型本轮没有逐一重做浏览器流程。后端授权写入的不明结果和恢复失败仍需单独故障注入，题库与跨问卷统计仍待开发。
