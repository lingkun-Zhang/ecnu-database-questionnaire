# 第二阶段演示讲解与自查

这份导读帮助先理解设计，再按页面展示；独立HTTP复验入口见[复验说明](phase2-verification.md)，完整页面操作见[演示步骤](phase2-demo.md)，验收范围见[逐项核对](phase2-acceptance.md)。下面使用已有[连续交付验收](phase2-delivery-review.md)的合成场景，不是一轮新执行记录，也不表示阅读者已经掌握代码。外部审阅估分不作为教师正式成绩。

## 先记住一个场景

同一道数字题V1允许0到7整数，V2改为1到5整数。作者有问卷A和B，接收者有问卷D：

| 问卷 | 固定的题目版本 | 已接受的答案 |
|---|---|---|
| 作者A | V1 | 0 |
| 作者B | V2 | 3 |
| 接收者D | V1 | 3 |

D另行授权汇总后，V1的两份答案为0和3，总和3、平均1.5；V2单独显示3。作者原始明细和CSV只有A的0、B的3，D的3只参与汇总。题目版本号与问卷发布版本号是两套编号；这轮D重新发布过，三份发布问卷共有四个发布快照。

准备演示时使用合成账号和独立教学场景，提前保存发布并确认计数。不要为试讲反复提交答案，导致现场数字与此表不符。页面填写预览不会产生正式答卷。

## 八至十分钟怎么展示

1. **第0至1分钟：说明变化。** 第一阶段已经能编辑、发布、填写和统计问卷；第二阶段让题目独立保存、复用和演化。打开题目管理，再指出第一阶段的问卷编辑入口仍在。
2. **第1至3分钟：看固定版本。** 打开V1/V2历史、A/B问卷来源及题库成员。说明“选择的是一份固定内容”，作者出新版、题库换版都不会替换已经保存的A。B不能合法提交0，因为它用V2。
3. **第3至5分钟：看修改和恢复。** 展示影响检查与确认/取消，再展示恢复记录：由V1内容生成V3，内容来源是V1，恢复前当前版是V2。若准备数据已经有V3，只展示记录；再次恢复会生成后续版本，不能仍称为V3。
4. **第5至7分钟：切换权限视角。** 接收者查看自己的D及独立汇总授权；作者查看V1的0/3汇总和本人明细。指出共享题目、允许汇总、读取原始答卷各是什么权限。可展示撤销共享后旧绑定仍存在的状态；完整新增拒绝流程按详细手册准备。
5. **第7至9分钟：解释统计与证据。** 说明两个内容版本分别计算，范围固定每卷自己的提交序号；展示对应测试函数及保存结果。明确哪些来自真实API、哪些是受控故障测试、哪些是页面检查。
6. **最后1分钟：说清取舍。** 简述下面三项解释和仍未验证的边界，结束后用正常停止入口保留数据。

任务书有三处未完全规定细节：本系统将“不创建新版”解释为取消保存或恢复，已有内容版保持不可变；他人问卷以稳定脱敏代号展示引用；跨卷统计先核对授权，再按内容版本分别解释。演示时说明理由即可，不说这些已获教师逐项认可。它们的完整依据见[需求解释](phase2-acceptance.md#已确认的规则与采用的解释)。

## 五个常见追问

**为什么需要三种题目标识？** `questionId`回答“是哪道题的系列”，`questionVersionId`回答“用了哪份固定内容”，`instanceId`回答“在这份问卷的哪一处出现”。同一题可以在一卷出现两次，两处必答与跳转不同，因此不能共用实例标识。来源存储和校验见[问卷服务](../backend/app/services.py)、[数据库结构](../backend/app/database.py)；找[固定来源测试](../tests/test_question_sources.py)中的`test_same_bank_question_can_have_two_local_instances_and_local_routing`对照。

**恢复V1为什么不直接把当前指针改回V1？** 这里把恢复记录为一次新的内容操作，所以V3复制V1内容，`parentVersionId`指向V1，`previousCurrentVersionId`记录V2。旧V1/V2和问卷固定引用都保留，之后仍能看懂何时恢复、恢复前是什么状态。实现见[题目服务](../backend/app/questions.py)的`restore`与`_append_version`，验证见[恢复测试](../tests/test_question_restore.py)中的`test_restoring_old_content_creates_v4_without_rewriting_history_or_survey_references`；该测试故意先建到V3，再恢复成V4，原则相同。

**题目共享了，为什么还不能看D的答卷？** 使用共享只允许在自己的问卷选题，不授予编辑原题或查看别人的答卷。D的所有者另行允许汇总，作者才把D纳入统计；该授权也不开放D的逐条回答。作者能读的原始明细仍只来自自己的A/B。实现见[共享服务](../backend/app/question_sharing.py)及[统计服务](../backend/app/question_statistics.py)的`set_grant`、`validate_scope`和`raw_rows`；验证见[统计测试](../tests/test_question_statistics.py)中的`test_use_sharing_does_not_grant_answers_and_survey_owner_can_authorize_aggregate`。

**为什么不把所有数字混在一起算，或者总取最新数据？** V2可能改变题意、选项或量纲，不能默认与V1可比，所以0/3的均值1.5只解释V1。翻页时若不断纳入新提交，汇总与明细会对不上，所以先固定范围。另一个边界测试中E截至序号3、F截至2，F后来新增序号3不能因不超过E的3就进入旧范围；序号只能在各自问卷内比较。看[统计服务](../backend/app/question_statistics.py)的`create_scope`与`summary`，以及[统计测试](../tests/test_question_statistics.py)的`test_multi_instance_routing_numeric_golden_and_independent_survey_boundaries`。平均值也应由总和除以有效作答数，不能直接平均各问卷均值。

**测试这么多，是否证明断网和所有页面都没问题？** 没有。533项后端通过、3项权限相关跳过及216项前端通过是本轮完整批次，251个子测试不能再加成独立用例。故障测试在真实MongoDB事务的指定钩子或驱动返回边界抛异常，验证回滚或原请求恢复；它不等于实际拔网线。67个连续HTTP请求和两个账号代表页面是另一层证据，也不表示全流程都由浏览器点击完成。对应[当前结果](evidence/phase2-review-results-20261029.json)、[共享恢复测试](../tests/test_question_share_recovery.py)和[交付复验](phase2-delivery-review.md)。

## 试讲后的自查

合上本文，用自己的话解释：A为什么仍能接受0，恢复为何不改变A，D的3为什么出现在汇总却不出现在作者明细，以及F的新序号3为什么不能混入旧范围。答不上来时回到对应测试看输入与断言，再实际演示。这里是练习建议，不把未发生的学习或人工编码写进报告。
