# 第一阶段项目介绍

项目叫“问川”，是一个基于MongoDB的在线问卷系统。创建者登录后设计和发布问卷，其他登录用户通过链接填写，系统自动保存和统计。

数据库设计另有[可复现的索引实测](index-experiment.md)：在两万份合成答卷中，游标页用索引检查31份，全表扫描检查20,000份；完整版本统计检查80份对20,000份。默认查询会自行选中已有索引；匿名条件仍需额外过滤，报告保留了这种成本。

## 可以做什么

创建单选、多选、文本和数字题；配置必答、选择数量、文字长度、数字范围和整数要求；根据单选、多选或数字答案跳转；设置截止、关闭、匿名和同人多填；查看整个问卷、单题、原始回答及CSV。

## 为什么是四个集合

| 集合 | 可以这样理解 |
|---|---|
| users | 账号簿，保存账号、密码哈希及注册时间 |
| surveys | 当前管理记录，保存所有者、草稿和收集设置 |
| survey_versions | 每次发布时留下的一份完整问卷说明书 |
| responses | 每次正式提交产生的一张独立答卷 |

题目、选项和规则通常一起读取，所以嵌入问卷定义。答卷会不断增加，所以独立保存，通过问卷和版本ID关联；没有把所有内容挤进一个无限增长的文档。版本快照的重复是为了保证历史含义，不是无目的复制数据。

## 后端值得讲的三个设计

**跳转由数据配置。** 规则写在问卷定义里，不把某份问卷的业务条件写死。服务端从入口计算实际路径，并检查全部跳转边是否有环。年龄由18改17后，旧成年分支的缓存答案不会被保存。

**修改草稿不改变旧答卷。** 发布会形成新版本。已经开始填写V1的人继续按V1作答，创建者后来发布V2不会让旧答案突然违反新约束。统计也按版本核算。

**并发与重复请求有明确结果。** 同一次提交重试会拿回原回执，不重复保存；不允许多填时，事务和唯一索引共同约束。提交、关闭、截止及政策变更通过同一问卷协调记录和事务处理先后，失败会回滚。

## 演示时讲什么

按demo.md从空白创建四题问卷。先故意输入年龄121、只选一项、只写一个字，展示配置驱动的校验；再用17和18展示跳过身份与进入身份的区别。提交后核算2份/1人、年龄均值17.5及匿名/实名明细。

讲数据库时重点回答：为什么嵌入题目、为什么独立保存答卷、为什么保留发布快照、哪些约束由MongoDB保证、哪些必须由服务端判断。讲AI时按实际过程说明生成、发现错误、修复和验证，不把AI执行写成自己亲手完成。
