## 保存与发布期间的编辑保护，2026年10月22日

问题来自编辑器的异步保存链路：点击保存或发布后，服务器写入和草稿/版本列表读回尚未全部完成，页面仍能继续编辑；读回结果可能替换这段等待期间的新输入。收集设置、历史复制等会重新读取草稿或元信息的操作也需要同样的边界。

修复使用原生disabled fieldset覆盖整个编辑区域，保持busy直到写入及所有必要读回结束。保存、发布、设置、历史复制、重新载入、打开历史以及离开/切换问卷等入口在busy时返回，避免第二次操作提前结束第一次操作的锁定。未改变服务器草稿CAS、发布幂等或任何数据库结构。

新增15项回归编译并执行实际App.vue setup，使用可控Promise分别停住真实前端逻辑的写入、草稿读回和版本列表读回边界，检查：

- 保存和发布在三个阶段持续busy，完整结束后才显示成功并更新已保存基线。
- 写入失败保留本地内容、修订和错误信息；重试参数保持正确，发布沿用原幂等标识。
- 草稿或版本列表读回失败后恢复操作，不错误显示成功，已保存基线与实际已完成阶段一致。
- 写入或版本读回期间退出并登录另一账号，迟到结果不恢复旧账号的问卷，也不追加旧账号私有读取。
- 忙碌期间重复保存/发布、设置、重载、历史操作和导航均不发送第二次HTTP请求。
- 收集设置刷新保留未保存定义；历史复制直到草稿及版本读回完成后才释放busy。
