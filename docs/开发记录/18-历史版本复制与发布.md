# 历史版本复制与发布

日期：2026年10月21日。范围：真实页面完成“历史V1复制为新草稿→编辑并保存→发布V3”，核对历史、填写和统计。现有逻辑通过，本轮新增[独立验收服务](../../tests/support/history_browser.py)及证据，未修改业务代码、前端、Schema、依赖或配置。

## 环境与观察方式

临时服务仅绑定127.0.0.1的随机端口，使用独立随机测试库和内存中的临时密钥，加载与交付目录一致的既有前端构建。通过真实API准备V1上限120、匿名110；V2上限100、实名90，各1份答卷。浏览器实际登录、点击、输入和选择版本；没有用程序直接调用页面私有函数或用接口代替这些页面动作。

服务在复制/保存/发布这三个真实HTTP写入完成后读取四集合完整文档，记录检查布尔值与合成测试数据摘要。请求、参数及实际响应原样传递，没有伪造状态或数据库结果。预期只允许草稿/修订/更新时间改变，或发布时新增相应快照并更新当前版本指针；账号、原V1/V2及两份答卷逐次完整文档比较。

“复制为新草稿”本身会立即PUT保存，不是只改浏览器内存；因此实际再修改标题、点击一次保存，才构成独立的编辑保存步骤。

## 实际流程

| 步骤 | 页面与数据库实际结果 |
|---|---|
| V2编辑页打开历史，复制V1 | 确认提示出现后复制完成，PUT 200；r2→r3，草稿完整恢复V1及上限120，当前发布仍V2/上限100 |
| 输入“历史恢复验收 V3（源自V1）” | 页面提示未保存，保存可用、发布禁用；服务器仍只有复制这一次写入 |
| 点击保存草稿 | PUT 200，r3→r4，只有标题不同于V1；保存禁用、发布可用；当前仍V2 |
| 保存后开始一次实际填写 | 标题V2、填写版本V2、上限100，证明保存未提前上线 |
| 编辑页发布新版本 | POST 201，V3来源r4，题目/稳定ID/限制继承V1，当前指针V3；修订仍4，设置修订1、提交序号2、政策锁true保留 |
| 检查旧填写与新填写 | 已开始的旧页仍V2/上限100；新开始为V3/上限120，输入110完成校验并进入选填备注页，没有点击正式提交 |
| 三版统计与明细 | V1：1份、匿名1、均值/总和110和原备注；V2：1份、匿名0、均值/总和90及原实名/备注；V3：0份、0人、无明细，固定范围序号仍2 |
| 历史比较V1→V3 | 三版仍存在，来源r1/r2/r4；只显示问卷标题变化，没有题目变化 |

三个数据库写后检查全部通过，状态依次200/200/201。最终只多了V3，未复制答卷；后续页面读取和填写求值之后，完整数据库快照仍等于发布后的快照。没有把新V3中输入110但未提交的动作算成新增答卷。

## 中断恢复与清理

第一次临时服务在对话切换后退出，记录为0次页面写入；本项目数据库服务也停止，第二次临时启动因此未就绪。先通过交付目录已有安全启动脚本恢复原服务，再核对第一份测试库的随机命名、独立问卷ID/公开ID、账号关联、两版定义和基准统计，仅清理匹配的自建测试库。

最终改用隐藏后台进程，避免直接执行会话承载长期服务。完整流程只计最终这一轮；没有把前两次环境恢复当作页面通过。结束后关闭自建的三个浏览器标签，通过stop.request正常退出临时服务，确认最终测试库已删除、数据库列表中不存在。原项目服务健康ok。

本轮没有验证复制确认的取消分支，也没有验证已有未保存编辑被替换的分支。点击时工具曾提示确认弹窗中断，但随后实际复制已完成；依据页面与数据库继续，没有重复点击或把它写成取消成功。
